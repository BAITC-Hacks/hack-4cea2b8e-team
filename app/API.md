# Бэкенд «Граф денег»: подключение интерфейса

Расчёт выполняется локально, без LLM и API-ключа. `pipeline.analysis.analyze`
используется одновременно CLI и HTTP API. Результат загружается в память при
старте приложения. Изменения parquet требуют перезапуска.

## Запуск для Аргына

Python 3.11+ и зависимости из существующего `requirements.txt`.
Команды выполняются из корня репозитория в подготовленном окружении:

```bash
python -m pipeline.run --data data --out out
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Для данных в другой папке перед запуском API задайте `DATA_DIR`.
Для CLI используется `--data`. `DB_PATH` задаёт путь к SQLite стартового
приложения. CSV доступны и без записи в `out` через HTTP-экспорт.

Интерактивная спецификация: `http://localhost:8000/docs`.
Машинная спецификация: `GET /openapi.json`.

Экран Кости: `http://localhost:8000/graph` (также `/graph.html`).
Старый стартовый экран пока остаётся на `/`.

## Совместимость с фронтендом Кости

Обновлено до коммита `b5f2b27` без конфликтов с локальным бэкендом.

- Идентификаторы клиентов во всех JSON-ответах передаются **строками**:
  `gid`, `src`, `dst`, `source`, `target`, `gids`, а также `center` подграфа.
  Их нельзя преобразовывать через `Number` или `parseInt`: значения в данных
  превышают `Number.MAX_SAFE_INTEGER`. Кластеры, суммы и счётчики остаются числами.
  CSV сохраняют исходные целочисленные идентификаторы.
- Карточки и узлы графа содержат `in_degree = n_payers`,
  `out_degree = n_receivers`, `passthrough_ratio` (число или `null`).
  Недостоверное отношение в этом поле возвращается как `null`.
- Графовые рёбра дополнительно содержат `source = src`, `target = dst`,
  `amount = sum_kzt`, `tx_count = n_tx` для совместимости.

## Экран исследования

По просьбе владельца восстановлено прежнее оформление Кости: светлый фон,
плавающие панели, значки ролей и топ-25. Связи прямые (`smooth: false`).
Начальная раскладка рассчитывается скрыто с фиксированным seed=42,
после стабилизации физика полностью выключается. Предусмотрен предел
ожидания 2 секунды. Готовые узлы не движутся сами; ручное перетаскивание
и масштабирование доступны. Автоматическая анимация фокуса убрана.

Экран использует `/api/top`, `/api/node/{gid}`, `/api/subgraph`,
`/api/search`, `/api/cluster/{cluster_id}`. Подграф по умолчанию ограничен
150 узлами; при ограничении показывается сообщение о скрытом окружении.
При ошибке загрузки подграфа демонстрационные данные не подставляются.
Vue и vis-network пока загружаются с CDN.

Пошаговый экран и оформление с круглыми значками отменены по просьбе
владельца; API прямых потоков и операций пары сохранён для дальнейшей
работы над аналитическим интерфейсом:

- `GET /api/node/{gid}/flows?direction=out&limit=5&offset=0`
- `GET /api/node/{src}/transactions?direction=out&counterparty={dst}`

`flows` агрегирует только прямые переводы выбранного направления. Сортировка:
сумма по убыванию, затем gid. Возвращает `card`, `nodes`, `edges`, `items`
(узел, ребро, доля, объяснение), суммы и число операций всего и показанной
страницы, количество контрагентов, `has_more` и `next_offset`.
Рёбра содержат даты `first_date` и `last_date`. Связи между соседями не
добавляются автоматически. Поле `hidden_counterparties` относится к текущей
странице; интерфейс считает число раскрытых связей отдельно.

## Контракт

| Метод и путь | Параметры / результат |
|---|---|
| `GET /api/health` | Состояние приложения, `graph_loaded`, `n_nodes` |
| `GET /api/overview` | `n_nodes`, `n_edges`, `n_transactions`, `n_seed`, `sum_kzt`, `n_clusters`, `n_components`, `n_isolates`, `n_truncated`, `n_seed_without_outgoing`, `period`, `roles`, `limitations`, `thresholds`, `priority_formula` |
| `GET /api/top` | `limit=25`, до 1000; список `rank, gid, role, priority_score, why` |
| `GET /api/clusters` | Все кластеры: `cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis`; `top_gids` — строка с разделителем `\|`, как в CSV |
| `GET /api/cluster/{cluster_id}` | `limit=150`, до 1000; узлы и внутренние рёбра выбранного фрагмента кластера |
| `GET /api/search` | `q` — непустой префикс gid; до 20 результатов `gid, role` |
| `GET /api/nodes` | Фильтры ниже, `q`, `limit=50` до 1000, `offset=0`; `{total, items, offset, limit}` |
| `GET /api/graph` | Фильтры ниже, `limit=150` до 3000; `{nodes, edges, total, truncated}` |
| `GET /api/node/{gid}` | Полная карточка, описанная ниже |
| `GET /api/subgraph` | `gid`, `hops=2` от 0 до 10, `limit=150` до 1000, `direction=both`; `{center, nodes, edges, truncated}` |
| `GET /api/node/{gid}/flows` | `direction=out` (`in` или `out`), `limit=5` от 1 до 20, `offset=0`; прямые связи и агрегаты |
| `GET /api/node/{gid}/transactions` | `direction=both`, `counterparty` — необязательный gid второй стороны, `date_from`, `date_to` в ISO-дате, `limit=50` до 1000, `offset=0`; `{total, sum_kzt, items, offset, limit}` |
| `GET /api/path` | `source`, `target`, `max_hops=6` от 1 до 10; `{source, target, found, gids, nodes, edges, max_hops, interpretation}` |
| `POST /api/common-receivers` | JSON `{"gids": [123, 456], "limit": 50}`; 2–20 разных узлов, `limit` до 200; `{gids, total, items, truncated, hops: 1}` |
| `GET /api/resilience` | `top=10`, от 1 до 100; размер крупнейшей компоненты и число компонент до/после удаления топа, `gids`, `interpretation` |
| `GET /api/export/{filename}` | `nodes_roles.csv`, `clusters.csv` или `top_nodes.csv`; файл CSV для скачивания |

Фильтры `/api/nodes` и `/api/graph`: `role`, `cluster_id`, `is_seed`,
`truncated`, `min_priority` от 0 до 1, `typology`. Совместно применяются через
«И». Сортировка — приоритет по убыванию, затем gid по возрастанию.

Роли: `consolidator`, `transit`, `distributor`, `terminal`, `coordinator`,
`peripheral`. Типологии: `structuring`, `layering`, `synchronized-inflow`,
`round-tripping`. В записях узлов `typologies` — строка с разделителем `|`;
пустая строка означает отсутствие срабатываний.

Направление `out` раскрывает получателей, `in` — плательщиков, `both` — оба
направления. Центральный узел всегда включён в подграф даже при `limit=1`.
Отбор идёт по расстоянию до центра, внутри одного расстояния — по приоритету.
Стрелки рёбер всегда сохраняют исходное направление денег.

Графовые узлы содержат `gid`, `role`, `role_score`, `cluster_id`,
`priority_score`, `depth`, `is_seed`, `truncated`, `sum_in`, `sum_out`,
`typologies`, `evidence`. Рёбра: `src`, `dst`, `sum_kzt`, `n_tx`.
Рёбра соединяют только возвращённые узлы. Фильтрация может скрыть посредников.

**Не путать два `truncated`:** на уровне ответа это ограничение размера
отображения, внутри узла — обрыв наблюдения на глубине сбора данных.
Для `/api/cluster/{cluster_id}` поле `cluster_id` обозначает кластер;
старое `center` сохранено для совместимости и тоже содержит ID кластера.

Карточка дополнительно возвращает `n_payers`, `n_receivers`, `n_tx_in`,
`n_tx_out`, `passthrough` (число или `null`), `ratio_reliable`, `component`,
числовые признаки типологий и `typology_evidence`. `warnings` и `next_steps` —
списки русских строк для аналитика. `priority_breakdown` содержит три
слагаемых: `role`, `turnover`, `connections`. Их сумма после округления до
четырёх знаков равна `priority_score`. `score_kind=rule_based_heuristic`.

Общие получатели — пересечение непосредственных получателей **всех**
переданных клиентов. `items` содержит `{node, sum_kzt, edges}`, сортировка —
по общей сумме переводов выбранных клиентов получателю. Это не поиск общих
получателей на произвольном числе колен.

Маршрут — один кратчайший **направленный** путь по числу связей. Если в
пределах `max_hops` его нет: HTTP 200, `found=false`, пустые массивы.
Даты не участвуют в поиске маршрута: наличие пути не доказывает прохождение
одних и тех же денег по этой цепочке.

Ошибки: HTTP 404 для неизвестного узла/кластера, HTTP 422 для неверных
параметров. Текст в `detail`. Ошибки схемы входных файлов и расхождения
агрегатов останавливают загрузку данных с объяснением.

## Аналитические ограничения

- Суммы входящих и исходящих относятся к выборке, а не полному балансу.
- Для seed и узлов на границе обхода отношение потоков не определяет роль.
- `role_score` — эвристика правила; она не обучена на размеченной выборке.
- Louvain использует неориентированную проекцию с суммой встречных потоков.
- Каждый изолированный узел имеет собственную компоненту и кластер.
- Внутренний оборот кластера включает только рёбра с обоими концами в нём.
- Временной транзит сопоставляет суммы по датам без повторного расходования
  исходящей суммы. Последовательность событий внутри дня неизвестна.
- Детектор дробления проверяет повторные близкие суммы между парой за
  короткий общий период; отдельные всплески внутри длинного периода может
  пропустить. Совпадение с правилом само по себе не доказывает дробление.
- Циклы проверяются до длины 4; они описывают связи, не доказанный возврат денег.
- `/api/generate` остаётся общим интерфейсом стартового LLM-модуля и не является
  помощником с доступом к графу. Не подключать его как источник фактов о сети.

## Проверено при реализации

15 существующих тестов прошли. Дополнительная временная проверка на данных
трека подтвердила совпадение API с CSV, внутренние обороты, изолированные
узлы, фильтры, направленные маршруты, общих получателей, транзакции,
ошибочные параметры, устойчивость к перестановке строк и граф без рёбер.
Файлы `tests/` не менялись; Аргын может закрепить эти сценарии в тестах проекта.

Полный прогон дал 2 248 узлов, 3 119 рёбер, 4 840 транзакций, 91 кластер,
35 компонент (включая 19 изолированных узлов) и 365 890 012,01 ₸ переводов.
Замер CLI: 4,3 секунды внутри команды расчёта, без установки зависимостей.

## Подписи, типологии и интерпретация потоков

Подписи на карте видны только у выделенного узла и узла под курсором.
Карточка показывает теги `typologies` с русскими названиями и
`typology_evidence`. Это признаки для проверки, а не доказанные схемы.

`ratio_reliable` и `is_seed` уже входят в API. Для seed, обрыва обхода
и неизвестной надёжности интерфейс показывает «Н/Д» с причиной.
Остальным показывается «Исходящие / входящие» и оговорка о неполной выборке,
а не «Доля транзита». Клиент 100000000331309100 не seed (depth=2).
Клиент 100000003684369100 — seed и имеет четыре флага типологий.

Проверка для Аргына: в текущем топ-25 — 18 coordinator, 4 consolidator,
3 distributor. Coordinator назначается раньше других содержательных ролей
при n_payers >= 5 и n_receivers >= 5. Половина priority_score зависит
от веса роли, причём coordinator имеет максимальный вес 1.0.
Нужно проверить пересечение правил и чувствительность ранжирования,
а не менять пороги ради равного количества цветов. Пороги в этой правке
не менялись.

## Проверка действий интерфейса

После проверки исправлены история первого перехода, выбор из результатов
поиска по префиксу, перекрытие фильтров карточкой и обработка запоздавших
ответов. При неуспешной загрузке клиента предыдущий граф сохраняется.
Новый клиент открывается со сброшенными фильтрами. Пустая выборка фильтров
имеет явное сообщение; включение роли восстанавливает карту.

Клик по стрелке открывает отправителя, получателя, сумму и количество
операций. Кнопка «Показать операции» вызывает transactions с counterparty
и direction=out (до 1000 строк, показанное и полное число указаны явно).
Оба идентификатора в карточке связи открывают соответствующего клиента.
Кнопка просмотра кластера подписана явно; числа относятся к внутренним
связям кластера. Начальная история включает первый открытый узел.

Проверены в браузере поиск полного/неполного/неизвестного gid, назад/вперёд,
фильтры ролей и кластеров, выключение всех ролей и восстановление,
кластер, карточка связи, операции пары, переход к получателю, сворачивание
и закрытие топа, легенда, перетаскивание и масштабирование. Проверена
ширина 390 px; панель фильтров прокручивается. Временная проверка JS
подтвердила сохранение графа при ошибке и игнорирование старого ответа.
15 существующих тестов прошли; дополнительная проверка API сверила все
страницы прямых потоков, суммы, доли, даты и операции для 99 получателей
и 5 плательщиков, а также пустые и ошибочные запросы.
